# Actionable migration review findings

1. **[P1] AI client construction can combine an old endpoint with a new credential.** `src/Modules/AI/DigitalBrain.Modules.AI/Integrations/AiCredentials.cs:28` reads current readiness and releases the current secret, while `StatusOf`/`Setting` reuse a five-second cached snapshot. `Providers/Common/OpenAICompatibleProviderFactory.cs:43-44` selects the cached endpoint before releasing the fresh key. Prime status for endpoint A/key A, atomically configure endpoint B/key B, and construct a new model client within the cache lifetime: it sends key B to endpoint A. The current rotation tests advance the clock past the cache lifetime and rotate only the key, so they miss this. Resolve endpoint, generation and secret from one revision, or reread/retry until the revision is unchanged. Add a deterministic endpoint+key rotation test with a paused release.

2. **[P1] Default profile/provider singleton clients bypass revision rebuilding.** `src/Modules/AI/DigitalBrain.Modules.AI/Clients/AIClients.cs:135-146` wraps default construction in a `RebuildingChatClient` whose generation always returns zero. When Default.Profile/Provider/Reasoning/MaxOutputTokens selects `ModelProfiles.CreateClient`, that method constructs a raw pinned provider pipeline (`ModelProfiles.cs:139-151`) without another rebuilding wrapper. After the first request, clearing or rotating the integration leaves the injected default IChatClient using the released old key indefinitely. The keyed preset path does have revision rebuilding, and CredentialFacts tests only that path. Keep model/profile selection pinned but drive the default pipeline by its selected provider integration generation, and test rotation/clear through the unkeyed IChatClient with Default.Provider or Default.Profile configured.

3. **[P2] GitHub optional credentials are still mandatory in the Aspire App projection.** `src/Modules/Microsoft/GitHub/DigitalBrain.Modules.Microsoft.GitHub.Aspire.Hosting/GitHub/GitHubAppHostingExtensions.cs:55-78` always adds and projects private-key, webhook-secret and client-secret parameters; the overload also requires a client ID and public OAuth origin. Runtime IntegrationSchema correctly marks ClientSecret/WebhookSecret optional, but the supported WithGitHubApp host path still requires supplying their secret parameters before an installation-only deployment can start/publish. OAuthCredentialFacts verifies optional absence against a fake handle rather than this adapter. Make OAuth/webhook projections optional independently of installation credentials and test an installation-only Aspire projection with only AppId/PrivateKeyPem.
