# Database connector migration

Supabase, ClickHouse and Postgres declare their own IntegrationSchema and ConnectorDefinition. Contracts options contain only ordinary settings; credential resolution and ResolveConnection are removed. Credentials seed under DigitalBrain:Integrations:{id}:ConnectionString, with postgres AdminConnection optional. The retired capacity-admin configuration root has no module reader or producer. ProvisionPerBrain is an explicit non-secret Postgres option, enabled by local hosted Aspire projection.

Runtime reads are asynchronous module-scoped handles. ClickHouse checks integration readiness on each operation and reuses its materialized provider until the revision changes. Postgres resolves and caches pools by the released credential and physical database, including per-brain origins. Supabase user requests read the per-brain supabase Connection through IModuleConnectionCredentials and never fall back to the deployment integration. The existing query/table API selects connection ID supabase; additional project selection would need an explicit connection ID in that API. SupabaseBackingStore is a separate internal integration-backed provider with pooled database operations; infrastructure health probes that provider without a user stamp or Connection. User neurons/tools still resolve only ConnectionSupabaseProvider. When UseBackingStore is selected, its startup initializes the deployment pool after Platform seeding. Postgres startup validates/parses AdminConnection when ProvisionPerBrain is selected and never reads it in the unselected mode. All configuration and environment keys derive from IntegrationSchema.Key and DigitalBrainConfiguration helpers. Connector metadata lists public neuron and signal contracts. Aspire adapters project integration seed environment keys, including the optional admin credential only in local hosted Postgres mode.

Removed Postgres module-created platform caller identity. Primary moved the migration contract into Framework with retained namespace/identity and added specific Platform-owned startup orchestration. No general impersonation API was added.
