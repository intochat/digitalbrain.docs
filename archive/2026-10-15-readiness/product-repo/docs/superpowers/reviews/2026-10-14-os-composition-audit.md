## Finding

Moving the entire product into C# requires more than removing a Flutter sidebar. Product composition currently lives in both the C# Flutter module and Dart shell, while feature bundles own only app interiors. The current source contains no `features/os/Home` or `features/os/Workspace` directory. The directory inventory also contains no Discover app. The present default is Ino, not automatic Discover: `WorkspaceNeuron.cs:13-14` seeds Ino only when Path is empty, and `workspace_app.dart:70-87` reads existing state, except for an explicit settings URL. Preserve this already-correct startup behavior while replacing the presentation model.

Path abbreviations below: `Flutter/` = `src/DigitalBrain.Modules/Google/Flutter/`; `Apps/` = `src/DigitalBrain.Modules/DigitalBrain/Apps/`; `Circles/` = `src/DigitalBrain.Modules/DigitalBrain/Circles/`.

## Proposed boundary

Use the existing four words. Workspace, Discover, Profile, Settings, Build, Connections, and Usage are app programs with synapses; persistent workspace state remains a neuron. Typed presentation targets and dock entries are data contracts, not a new execution abstraction.

- **Workspace app** owns the root composition: one full-size focused target, bottom launcher/pins on the left, ordered open targets in the middle, Ino and usage on the right. It owns default selection, pin order, close/focus behavior, launcher visibility, and deliberate Discover opening.
- **Workspace state neuron** owns authoritative focus, open target order, pins, explicit navigation history, and durable commands. Product choices are supplied by the app rather than hardcoded Ino/application-key assumptions. Use concrete arrays, revision checks, stable operation IDs, and replay-safe operations.
- **App/profile/chat targets** resolve through one typed host. Preserve independently addressable document/chat roots: an app is installation/program ownership, not necessarily one view. Identity and source-brain membership travel with the target rather than being inferred from an arbitrary string suffix.
- **Profile app** composes identity, authorized published apps/posts, and available chat actions within the same host. Public publisher identity and circle-visible person identity need an explicit mapping and privacy policy; do not collapse principal, account, and brain identifiers.
- **Discover app** owns browsing/search/feed composition and appears only after explicit user selection. Opening an app from Discover, completing a fork, or receiving a background signal must not make Discover the new startup page automatically.
- **Modules** provide validated capabilities, persistence, public/private read boundaries, publication/install security, renderer schema and primitive neurons. They must not enumerate apps and decide the user's OS layout.
- **Flutter connector** owns generic rendering, accessibility, focus/input delivery, theme/motion primitives, resource loading, transport/reconnect, and essential connection/auth failure UI. No knowledge of product app names, sidebar regions, profile/feed semantics, launcher entries, or dedicated settings/build/usage screens.

## Blocking design decisions

Security evidence: `Apps/DigitalBrain.Modules.Apps/Apps/AppNeuron.Presentation.cs:86-93` requires stamped App kind, exact AppId, and matching ProgramRevision for Present; `:17-21` restricts mounted references to the same brain; `:60-66` protects reserved blackboard writes. Preserve these checks for Workspace's own published root. They do not by themselves authorize arbitrary foreign app/profile mounting. This source check is an assignment identity/revision guard, not evidence of a separately verified signed UI bundle.

Usage gap: `Flutter/app/shell/lib/workspace/compute_usage_panel.dart:87-119` directly calls HTTP client usage reads. `src/DigitalBrain.Platform/DigitalBrain.Platform/Compute/ComputeEndpoints.cs:18-39` scopes usage to the current brain and balance to the stamped account, then reads platform IUsageGrain/ILedgerGrain. An app-facing read-only usage neuron/facade is needed to compose Usage in C# without exposing platform grains. Preserve account-versus-brain distinction and bounded grouping/recent queries. Do not expose the simulated credit endpoint (`:42-49`) as an incidental consequence of adding read access.

1. Current Present shape is Sphere/Side/Main; simply hiding Side loses valid app content. Define how apps migrate internal navigation into their own layouts and how the OS root mounts arbitrary typed children. The renderable palette/UiPart and cross-app subscription scopes are explicitly open fronts in CLAUDE.md; settle them before implementation.
2. Move `SpaceComposer` policy as well as Dart geometry. Otherwise the OS remains fixed module code under a thinner shell.
3. Workspace must observe other apps' presentations and publish one derived root without arbitrary cross-app write authority. Specify authorized read/subscription scope, assignment revision checks, and reserved state ownership.
4. Avoid circular boot dependencies: Workspace cannot require its own completed presentation to discover apps. A generic unavailable/loading host must display failure while preserving state; it must not silently navigate to Discover.
5. Replace suffix-based profile acceptance (`WorkspaceNeuron.cs:63-71`) with canonical typed targets while retaining actual authorization on reads. Membership revocation must invalidate focused content and pins safely without leaking cached content.
6. First-party defaults and reconciliation differ. Existing brains need explicit authorized installation of new OS bundles; keep edited copies intact. Plan failure/recovery if a Workspace update compiles but fails to present.
7. Native account/OAuth/browser permissions are connector capabilities; moving the settings UI into C# does not grant scripts custody of credentials or authority to bypass human authorization.
8. Root composition must be convergent: rendering does not modify focus, selected chat, form draft, read receipts, or pins. Background completion updates content without reopening closed views.

## Delivery phases and acceptance

1. **Contract/design checkpoint.** Resolve root composition, view target identity, multi-view app support, subscription authority, source identity mapping, and first-brain fallback. Record supersession of 2026-10-13 neuron-space orbit/side-main design. Keep 2026-10-12 composition-ownership lessons about input versus projections, but do not copy its obsolete Workspace APIs.
2. **State and host primitives.** Add generic typed targets, pin/open order and focus commands. Facts: same-operation replay, stale revision handling, persisted reactivation, close focused/last item, profile and chat targets, inaccessible target recovery, independent views from one app. No new product composition in Flutter.
3. **Workspace bundle.** Compose full canvas and bottom dock in C#. Facts: no left sidebar; launcher and pins left/open views middle/Ino and usage right; explicit Discover; focus survives reconnect/restart/brain switch; background updates do not steal focus. Only explicit navigation changes focus.
4. **Shared product views.** Move settings, connections, build/configuration and usage branches into C# app presentations. Compose Profile/Discover/Circle/chat into same host. Keep publication preview read-only and fork/install commands behind existing authorization and receipt paths. Test unavailable release, digest identity, duplicate fork, edited-origin protection, and denied membership.
5. **Remove old composition.** Retire orbit/layout policy from SpaceComposer and hardcoded Dart route/widget branches after equivalent paths run. Architecture checks should prevent product app identifiers and special-view composition from reappearing in connector code.
6. **Live acceptance.** Build affected projects, LSP diagnostics, module unit/E2E suites, Flutter analyze/tests; then Aspire all resources Healthy. Drive neuron workspace commands, profiles, publication preview/fork and app interactions through digitalbrain-mcp; read state and derived roots after reconnect and runtime restart; inspect matching traces/logs. Visual review confirms full canvas/dock and accessible keyboard/narrow layout. Compilation alone is not behavior acceptance.

Additional regressions: conversation draft and explicit unread receipts survive remount; selecting a publication never installs it; fork completion never steals focus unless explicitly requested; revoked membership clears active person/chat data; corrupted/missing app presentation retains navigation state with recovery affordance; reordered pins and open views survive persistence; newly published app appears only in authorized discovery; Circle brain authorization stays distinct from personal brain fork policy.

No tests have been executed for this audit. All proposed phases are unimplemented and runtime-unverified.
