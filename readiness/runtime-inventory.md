## Concrete gaps versus unverified behavior

The explicit implementation boundaries found here are narrow: Engineer does not build modules; workshop source editing is disabled without a configured root; Files exposes supported Windows browsing/text preview rather than arbitrary cloud-drive or file mutation; memory table schemas require new keys rather than in-place schema migration. FilmCraft/PhotoCraft require their studio/page/model configuration, and model-driven apps require their configured services. Those constraints should be stated specifically. The many remaining acceptance tests above are **verification work for implemented features**, not evidence that those features must first be built.
