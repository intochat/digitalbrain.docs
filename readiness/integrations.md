# Connectors and data integrations

This is an implementation inventory, not a list of proposed integrations. **Every live/external and production result below is unverified in this audit.** Implemented adapters remain implemented even when credentials or a production test are absent; declared-only capabilities are called out separately.

Snapshot: DigitalBrain `faddacfc3b5e7cf3a74adfd0efcf8a17e277540b`, 17 October 2026. Source tree was clean when inspected. Paths are relative to DigitalBrain; module roots below are under `src/DigitalBrain.Modules/`. Each root contains its named implementation project and `tests/` projects. Test evidence means inspected test code, not a fresh execution or live-provider certification. See [AI providers](./providers) for individual model providers and [billing](./billing) for Stripe and payment implementation.

## Connection lifecycle

`src/DigitalBrain.Platform/DigitalBrain.Platform/Connections/ConnectionEndpoints.cs` implements connection operations, and `ConnectionBindings` resolves configured bindings. `OAuthLoginFlow`, `OAuthLoginRequests` and `OAuthTokenExchange` implement authorization/state/token exchange. `Secrets/SecretSealer` encrypts stored secret material using wrapped keys. Platform tests cover OAuth, ownership and token-endpoint stubs; those do not replace each connector's real consent, refresh, revocation and user-outcome acceptance test.

The remaining implementation limitations are specific: Gmail exposes connection/push support rather than full mailbox operations; Tavily search has declarations but no identified execution adapter; default speech synthesis remains unavailable until explicitly registered; AI user BYOK and realtime sessions are not implemented in the inspected client layer. Missing production checks for the other implemented adapters are a separate verification backlog, not evidence that their code is unfinished.
