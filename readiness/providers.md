# AI providers and operations

The AI layer is implemented, with separate adapters for the providers below. **None of the external providers, local model runtimes, or production model deployments was exercised in this audit.** That verification gap does not mean their adapters are missing. Conversely, registration of a connector or a model name does not prove that a vendor currently serves that model.

Snapshot: DigitalBrain `faddacfc3b5e7cf3a74adfd0efcf8a17e277540b`, 17 October 2026; application working tree clean when inspected. Source paths below are relative to DigitalBrain. `AI/` abbreviates `src/DigitalBrain.Modules/AI/`; implementation paths are under `AI/DigitalBrain.Modules.AI/`, contracts under `AI/DigitalBrain.Modules.AI.Contracts/`, and test names under `AI/tests/DigitalBrain.Modules.AI.Tests/`, unless stated otherwise. Tests listed are inspected source evidence, not newly executed tests or proof that every provider passed.

The compatible factory contains an embedding creation method, but that does **not** establish an embedding product for every subclass. The shipped embedding catalog includes only OpenAI, Google and Ollama. Likewise, an arbitrary endpoint override is protocol configurability; it is not a dedicated, tested Azure OpenAI, Groq, Mistral, direct DeepSeek or other vendor integration.
